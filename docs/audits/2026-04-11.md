## Execution rules (applies to every session)

- **Re-verify line numbers before editing** — files drift; use `Grep` with the quoted symbol or comment anchor from the item before opening `Edit`.
- **Do not batch sessions.** One session = one commit = one strikethrough pass.
- **Backend sessions:** run `make lint && make test` before committing.
- **Frontend sessions:** run `make lint && make test-front`, then open the changed screens via Chrome DevTools MCP (login via `DEBUG_LOGIN*` from `.env.local`), check the console, navigate to 1–2 adjacent pages to catch regressions. Do not mark done without visual confirmation.
- **Mark items done inline** with `~~strikethrough~~` + short note (`fixed: <commit hash>` or `fixed: <one-line>`).
- **Skip an item** if re-verification shows it no longer applies; leave a note explaining why instead of deleting.

## SESSION-4 — Frontend rendering waste
*All items in this session require the DevTools visual check. Use the Preact DevTools profiler to confirm re-render counts dropped.*

- **[FE-1] HIGH** | `frontend/src/pages/Library.tsx:71-82` *(re-verify; look for 10+ consecutive `useTitleStore` calls)* — multiple separate store subscriptions cause a re-render on every unrelated store change.
  - **Fix:** Consolidate into one shallow-selected subscription. Zustand pattern: `const { titles, total, loading, sort, filter, ... } = useTitleStore(useShallow(s => ({ titles: s.titles, total: s.total, ... })))`. Import `useShallow` from `zustand/react/shallow` if not already present.
  - **Verify:** Profiler — flip a filter, confirm Library renders once, not N times.

- **[FE-2] HIGH** | `frontend/src/components/PosterCard.tsx` + `frontend/src/components/TitleCard.tsx` — each card subscribes to the store; flipping sort re-renders every card.
  - **Fix:** (1) Wrap both components in `memo()` from `preact/compat`. (2) Replace full-store subscriptions with narrow selectors returning only the primitive each component needs (e.g. `const sortField = useTitleStore(s => s.sort.field)`). (3) Pass anything card-specific via props, not store.
  - **Verify:** Profiler — scroll the library, confirm cards don't re-render when unrelated state changes. (Temporarily add a render-count log in one card during verification; remove before commit.)

- **[FE-3] MEDIUM** | `frontend/src/pages/AdminTasks.tsx` *(re-verify line for `filteredTasks`)* — filtered list recomputed every render.
  - **Fix:** `const filteredTasks = useMemo(() => (data?.tasks ?? []).filter(...), [data, filter])`.
  - **Verify:** Load `/admin/tasks`, filter between All/Failed/Dead, confirm list updates. `make test-front`.

- **[FE-4] MEDIUM** | `frontend/src/pages/Library.tsx` — `useEffect(() => { fetchTitles() }, [fetchTitles])` re-fires whenever `fetchTitles` reference changes. Zustand methods are stable *only* when selected individually (`useTitleStore(s => s.fetchTitles)`); otherwise the returned object is new each render.
  - **Fix:** Select the method with its own narrow selector: `const fetchTitles = useTitleStore(s => s.fetchTitles)`. If FE-1 already landed, include it in the shallow-select block.
  - **Verify:** Network tab — load Library, confirm exactly one `/api/titles` request (not two).

## Out of scope (deliberately dropped)

- **Stats `overview()` + `funStats()` consolidation** — 15+ queries, too tangled for a single session, speedup unclear vs. risk. Revisit only if `/api/stats` becomes a visible pain point.
- **Refresh worker pool** — `APILimiter(2, 1)` caps throughput at 2 req/s globally, so parallelizing gives marginal wall-clock win vs. concurrency risk.
- **Event-driven task queue wake-up** — current 30s poll is fine; reactive wake-up is a cross-service change for no user-visible win.
- **TMDB response in-memory cache across a refresh batch** — duplicates are already addressed in BG-2; cross-title cache would need invalidation.
- **`clsx` tree-shaking, TitleCard chip memoization, srcset for poster thumbs** — Explore agent raised them but the gains are <5ms each.
