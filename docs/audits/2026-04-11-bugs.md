# Audit bugs — 2026-04-11

## Contexte

Passe bugs complète après clôture des audits 2026-04-09 (code) et 2026-04-11 (optimisation). 42 trouvailles sur l'ensemble Go backend + Preact frontend + intégration TVDB (hot spot après 4 `fix(tvdb):` récents). Zéro vulnérabilité critique de sécurité ; essentiellement des erreurs silencieuses sur writes DB, des garde-fous manquants sur les conflits de cross-reference, de la résilience TVDB, du teardown goroutine, et de l'a11y frontend.

**Statut global :** 8 / 42 — En cours.

## Protocole d'exécution (sous-agents Sonnet, 1 session par invocation)

1. **Une session par invocation. Ne PAS enchaîner automatiquement.** Chaque session s'arrête et attend l'ordre explicite de l'utilisateur (`SESSION-N`) avant de reprendre.
2. Re-vérifier chaque `file:line` avant d'éditer — les numéros dérivent quand les sessions précédentes ont modifié les fichiers.
3. Ordre des opérations dans une session :
   1. Faire les modifications de code.
   2. Lancer `make lint` puis `make test` (ou `test-front` pour les sessions frontend). Corriger toute régression.
   3. **Avant le commit** : mettre à jour ce fichier d'audit (barrer les items terminés, passer l'en-tête de session à `DONE`) ET ajouter une ligne par session dans `CHANGELOG.md` `[Unreleased]` sous la bonne catégorie.
   4. Committer — code + audit + changelog dans un seul commit. Message en français, format `<type>(scope): description`, trailer `Co-Built-By: Claude (<quip>)`.
4. Ne PAS ajouter de features, refactors ou abstractions au-delà du strict nécessaire.
5. Si une trouvaille se révèle être un faux positif à la re-vérification : la marquer `~~FAUX POSITIF — raison~~` et passer.

## SESSION-2 — Résilience de l'enrichissement TVDB — **HIGH** — STATUS: TODO

**Risque :** Réponses TVDB partielles qui corrompent l'état disque ou qui font sauter silencieusement des updates métadonnées. Le CDN artwork TVDB peut bloquer des goroutines indéfiniment.

**Fichiers :** `internal/service/background.go`, `internal/service/matching/tvdb_covers.go`, `internal/service/matching/tvdb.go`, `internal/service/matching/tvdb_details.go`

- [ ] `background.go:202` — `refreshFromTVDB` ne persiste que si `update.CoverURL != nil`. Étendre pour persister aussi les autres champs métadonnées que TVDB peut renvoyer (overview, genres) quand le fetch cover échoue ou est sauté. Si les détails TVDB sont utiles sans cover, construire l'`update` en conséquence. Sinon, documenter la limitation volontaire par un commentaire d'une ligne.
- [ ] `tvdb_covers.go:59` — Sur erreur `io.Copy` : `os.Remove(destPath)` avant de retourner, pour ne pas laisser de fichier partiel.
- [ ] `tvdb_covers.go:17` — `DownloadCover` utilise `c.httpClient.Get` (bien) mais vérifier que le `httpClient` du `TVDBClient` a bien un timeout non-nul (≤15s) à la construction. Lire `NewTVDBClient` ou équivalent. S'il manque, le setter.
- [ ] `tvdb_details.go:184,197` — `strconv.ParseInt` sur TVDB `remoteIds[].ID` : sur `err != nil`, `log.Printf("tvdb: malformed remote id %q for source %q", r.ID, r.Type)` au lieu de retourner silencieusement 0. Garder le fallback, juste logger.
- [ ] `tvdb.go:44` — `body, _ := json.Marshal(loginPayload)` dans `Login` : vérifier l'erreur. Un échec de marshal ici c'est une struct mal formée — bug dev, remonter explicitement.

## SESSION-3 — Gestion des conflits de cross-reference — **HIGH** — STATUS: TODO

**Risque :** La détection de conflit downgrade `match_status` en `pending_review` mais laisse les IDs conflictuels en place. Au refresh suivant, le même conflit re-trigger le même downgrade — boucle infinie de pending_review. Les overwrites inconditionnels de slots vides peuvent corrompre des matches validés à la main.

**Fichiers :** `internal/service/matching/pipeline.go`

- [ ] L505-508 — Mismatch IMDB : sur conflit, trancher la source canonique (par défaut TMDB — c'est le matcher primaire). Réverter `result.IMDBID` à `tmdbRes.imdbID` (ou le vider) avant de passer à `MatchStatusPendingReview`. Logger les deux sources nommées.
- [ ] L511-514 — Mismatch TMDB ID : même traitement. Canonique = ce qui est déjà sur le titre (IDs Plex-sourcés l'emportent sur les remote IDs TVDB). Ne pas overwrite `result.TMDBID` avec `tvdbRes.tmdbID` en cas de conflit.
- [ ] L116-119 (chemin early-return pour IDs Plex-sourcés) — relire ce bloc. Si `enrichFromIDs` est appelé avec `result.TVDBID == 0`, s'assurer que le check de conflit L511 tourne toujours après lookup TVDB (ou sauter explicitement TVDB quand Plex a tous les IDs et documenter pourquoi).
- [ ] `mergeIDs` (grep la fonction — référencée ~L772 dans l'audit précédent) : vérifier que les fills inconditionnels de slots vides sont safes. Si un slot vient de la table `cross_refs` et que `result` runtime a une autre valeur, la DB ne doit PAS overwrite. Ajouter un commentaire sur la précédence, ou gater dessus.

**Vérification :** `make test ./internal/service/matching/...`. Ajouter un test unitaire pour le chemin "mismatch IMDB → revert + downgrade" s'il n'existe pas.
